Overview

The project studies how data structures affect three different jobs: finding routes, ranking posts, and checking records.

Shortest paths

The C++ benchmark runs Dijkstra with three min-priority queues and compares all resulting distances.

Ordered feeds

Two Python trees support the same feed operations. The benchmark shows what changes when a tree also orders nodes by score.

Review integrity

A SHA-256 Merkle tree commits to a sequence of reviews and supports proofs for individual records.

Heap and Shortest Paths

Dijkstra reads an undirected weighted edge list. It requires nonnegative weights and uses a priority queue keyed by tentative distance.

Binary heap

An array stores nodes and their positions. Sift operations restore heap order after insertion, extraction, or a decrease.

Fibonacci heap

A forest defers consolidation until extract-min. Cuts and cascading cuts restore order after a decrease.

Hollow heap

Stable item handles follow items to fresh nodes. The queue discards hollow roots during extraction and consolidates the surviving roots.

Experiments A and B

Experiment A runs Dijkstra on road networks. Experiment B exercises priority queues with synthetic operations. The consolidated benchmark reports insertions, extractions, decreases, and elapsed time.

Parallel and tracked runs

The bonus code runs independent sources over one graph and records changes in the Fibonacci heap over the course of Dijkstra.

Heap Inputs, Outputs, and Experiments

Graph format

Use one from–to–weight triple per line. Vertex IDs start at zero, and the highest ID determines the number of vertices. Lines beginning with # are comments. The loader treats each edge as undirected and rejects negative weights.

Tracing the sample

From vertex 0, the route to vertex 1 improves from the direct cost of 8 to a cost of 3 via vertex 2. The final distances to vertices 0 through 4 are 0, 3, 2, 5, and 8. Vertices 5 and 6 are unreachable from 0.

Reading the benchmark

Inserts count the first discovery of each vertex. Decreases count improvements to a vertex already queued. Extracts count removals of the current minimum. The benchmark compares distances, since equal-cost routes can have different predecessors.

Optional coursework runs

Experiment A applies Dijkstra to a road graph. Experiment B profiles synthetic insert, extract-min, and decrease-key operations. The parallel run assigns independent source vertices to workers over a shared graph. The evolution run exports CSV counters for the Fibonacci heap plotting script.

Road data and filenames

The release package contains Hongkong.road-d, Chongqing.road-d, Shanghai.road-d, and ShanghaiNew.road-D. Use the exact filename on systems that distinguish uppercase and lowercase letters.

Treap and BST Feed Study

Both trees order posts by timestamp and post ID. The treap also keeps higher scores above lower scores, so its root holds a most-popular post.

Feed operations

Both implementations support adding and replacing posts, likes, deletion, popularity lookup, and recent posts. An ID map helps find a post for updates.

Ordered workload

Chronological insertion can make a plain BST a chain. A treap rotates when a child outranks its parent. The resulting height depends on how scores relate to timestamps.

Benchmark metrics

The study measures height, rotations, average insertion and deletion time, and the time to query the most popular post. The notebook also shows tree shapes and feed operations.

Input data

The command-line demo and notebook run on synthetic data. A compatible Reddit submission dump can be streamed from compressed JSON Lines for a separate run.

Feed Operations and Benchmark Method

Post identity and ordering

Each post has an ID, timestamp, and score. Both trees use the timestamp and ID together as the ordering key. Adding an existing ID replaces the previous entry.

Likes and deletion

The ID map locates the entry to update or remove. The BST can increment a score in place. The treap reinserts the liked post at the new priority so the score ordering stays valid.

Popularity and recency

The BST scans for the highest score. The treap returns its root. Both trees find recent posts by visiting nodes in reverse timestamp and ID order.

What is timed

The benchmark measures adding posts, looking up the most popular post, and deleting posts. It reports average operation times and measures tree height before deletion. The notebook adds tree shapes, rotations, likes, and recent-post examples.

Reproducing the workload

The default CLI generates 1,000 chronological posts from a fixed score sequence. Use --posts to change the size or --dataset to supply a compatible compressed Reddit dump. The synthetic results depend on how timestamps and scores are distributed.

Merkle Tree and Review Integrity

The loader reads JSON Lines and selects review ID, product ID, rating, and review text. The tree commits to those fields in input order.

Tree construction

Each record becomes a leaf digest. Parent hashes combine child digests, and an unpaired child is repeated for that level. The final root also commits to the leaf count.

Inclusion proofs

The proof carries the sibling hash and side at each level. Verification recomputes the root from the candidate leaf and proof, then compares it with a trusted digest.

Tamper detection

The sample verifies an original review and rejects a changed leaf. The interactive menu can also save a trusted root for the session and demonstrate an edit after reloading a changed copy.

Scope of the check

Verification covers the chosen fields, ordering and record count. It depends on getting the expected root from a trusted source.

Review Fields, Proofs, and Tampering

JSON Lines input

Each line contains one review object. The loader reads review_id or reviewerID, asin, overall, and reviewText. When the ID is absent it creates one from the record position.

Hash construction

A leaf hashes the four selected fields as an ordered JSON array. Leaf, parent, and root hashes use separate prefixes. The tree repeats the final child at odd levels, and the root commits to the number of leaves.

Proof contents

Each proof step supplies a sibling digest and its side. The verifier uses that side to combine hashes in the correct order, then checks the resulting digest against the trusted root and record count.

Interactive workflow

Load and preview the reviews, build the tree, and save the root for the session. Then verify the current tree, request a proof by review ID, or run the edit simulation. The simulation writes a separate changed copy and rebuilds the tree after reading it back.

Scope and scaling

Changing a covered field, the input order, or the record count changes the commitment. Fields outside the selected four are outside the check. The scaling menu measures tree construction on available record prefixes.

Results and Trade-offs

Shortest-path agreement

The three queues agree on distances for both the sample graph and the 43,620-vertex Hong Kong graph. Compare timings on the same input and build before drawing performance conclusions.

Feed height at 1,000 posts

The BST reaches height 999 and the treap reaches height 22 on the synthetic run. The treap's height depends on the relationship between scores and insertion order.

Proof size and integrity

Building the tree takes linear time in the number of records. A single inclusion proof needs logarithmically many sibling hashes. A changed review fails against the original trusted root.

How to Compile and Run

Quick Start

Run from the repository root. The Python sample demos use the standard library. For C++, use CMake and a C++17 compiler.

Quick Start
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/heap_benchmark data/sample.road-d
python -m treap
python -m merkle data/sample-reviews.jsonl

More Ways to Run

The first command starts Dijkstra at vertex 2. The second opens the interactive Merkle menu. The last two prepare the optional Reddit workload.

More Ways to Run
./build/heap_benchmark data/sample.road-d 2
python -m merkle
python -m pip install -r treap/requirements.txt
python -m treap --dataset data/RC_2019-04.zst --posts 10000

With Visual Studio, run ./build/Release/heap_benchmark.exe. With MinGW, use -G "MinGW Makefiles" at configure time if needed. Set -DBUILD_COURSEWORK_EXPERIMENTS=ON to build the standalone heap experiments.
